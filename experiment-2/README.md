# Experiment 2: compare two selectors on 40 fixed problems

Experiment 2 compares Jev and OpenAI after a simple search has narrowed a software problem to five candidate files. It asks: **how often does each service choose a historical reference file, and how long does its answer take?**

You can read [the completed analysis](../reports/experiment-2/analysis.md) without installing anything or making paid calls.

## The experiment in plain language

1. Choose 40 different historical problems from the public SWE-bench Lite test set using a fixed selection rule. Exclude the original five pytest cases.
2. Save the chosen problem list before searching code or contacting the AI services. This saved list is the **manifest**.
3. Download the public source at the revision before each historical fix. Read it as text; do not install or execute it.
4. Use issue/source word matches to rank eligible Python files. Keep the top five and prepare short, line-numbered excerpts.
5. Send the same issue and five excerpts independently to Jev and OpenAI. Each service chooses one option.
6. Validate the response, record elapsed time, then compare the selected file with the historical changed-file labels.

The local search, not Jev, builds the shortlist. The labels are kept out of both search features and AI requests. All selected problems remain in the main score, including missing-answer shortlists, preparation failures, and provider failures.

## Recorded outcome

| Measure | Jev | OpenAI gpt-6-astra |
|---|---:|---:|
| Correct choices across all selected problems | 15/40 (37.5%) | 17/40 (42.5%) |
| Correct choices when a reference was available | 15/17 (88.2%) | 17/17 (100%) |
| Valid responses | 40/40 | 40/40 |
| Average response time | 185.7 ms | 2,918.4 ms |

Search included a reference file in only 17 of the 40 shortlists. The other 23 could not earn a hit with any valid choice. Those 23 stay in the overall denominator. Six tasks triggered the original clue checks; flags were reported rather than used to remove tasks.

Jev's average response time was about 15.7 times lower in this run, while OpenAI had two more hits. This is file selection, not bug repair. The sample is small, and historical public tasks can have appeared in training.

## Where the Jev template is

In `bench.mjs`, the function `bodies(e)` builds both providers' requests. Its `jev` section contains:

```text
model: jev-latest
state.issue: the original issue
questions.file.type: choice
questions.file.instructions: choose the most relevant file
questions.file.criteria: f0, f1, f2, f3, f4 with file paths and excerpts
```

`call()` sends that body to `https://api.typesafe.ai/v1/systemone` using `TYPESAFE_API_KEY` from the environment. It reads `answers.file.choice`, checks that the option exists, and maps it to the file. OpenAI receives matching evidence through its own request format. There is no separate Jev-template file or Jev code added to upstream projects.

For a developer reading the program: `sample()` chooses IDs, `retrieve()` ranks files, `prepare()` creates inputs, `bodies()` builds requests, `call()` contacts a provider, `summarize()` calculates results, and `run()` coordinates the run. See [the integration guide](../docs/JEV-INTEGRATION.md).

## How to use it without paying

All commands below start in the project's top-level folder, the one containing the main `README.md`.

First, check the program with fake responses:

```powershell
node .\experiment-2\test.mjs
```

On a **fresh checkout**, prepare the exact published sample, then preview its requests:

```powershell
node .\tools\prepare-replay.mjs 2
node .\experiment-2\bench.mjs run --dry-run
```

Preparation downloads public material but makes no paid provider calls. It checks the dataset's recorded content fingerprint. The helper refuses to overwrite existing local data. If this computer already has the completed experiment, skip preparation and read the saved reports; the dry run can still validate the prepared inputs without AI calls.

## Optional paid run

Use a prepared checkout with no existing report for that run. Enter keys using the [secure PowerShell steps in the main guide](../README.md#optional-make-a-new-paid-comparison), then run:

```powershell
# Small connection check: up to four paid calls
node .\experiment-2\bench.mjs run --smoke

# Full comparison: up to 80 paid calls
node .\experiment-2\bench.mjs run
```

Here, **smoke uses the first two full-run tasks again**. The full run makes fresh calls for them and writes a separate report. Do not combine the smoke rows with the full score or describe this setup as a cold-cache comparison. Freeze all settings before smoke; do not tune based on its answers.

An existing report causes a refusal rather than an overwrite. Do not delete the original report to force more paid calls. If interrupted, some entries can show in-flight or unattempted status; keep those records. No automatic paid resume/retry is implemented.

## Fixed rules for readers who need technical detail

- 40 tasks, selected by fixed SHA-256 seed ordering; seed `jev-experiment-2-v1`. The selected set spans nine repositories. It is not balanced by repository.
- Search considers production Python files, excluding the defined test, documentation, example, and benchmark paths. Ranking uses the sum of `log(1 + matching-term frequency)` from issue/path/source text, with path tie-breaking. It is not oracle search.
- Five files, at most 3,000 excerpt characters per file. Excerpts are centered around a strong lexical match and include line numbers.
- Original shared selection instruction; OpenAI requests JSON choice output. Requested models: `jev-latest` and `gpt-6-astra`. Actual returned model identifiers are recorded.
- Providers run one after another, alternating which goes first by task. Both have 60-second timeouts.
- Accuracy includes every selected task. Successful-response timing summaries and paired successful timings are explicitly identified. The elapsed time includes response transfer and parsing, not source retrieval or bug repair.
- Invalid choices, malformed replies, HTTP errors, timeouts, network errors, and preparation failures are recorded. Tokens and costs are recorded only when returned; missing values are not made up.
- Clue flags are checks, not proof that the unflagged tasks contain no clues. The historical patch, hidden-test labels, hints, and reference paths are not provider-request features.

## If preparation fails

Read the error and any `data/preparation-blocker.json`. Preserve the selected manifest. If an official JSON export is available and independently verified, the fresh-checkout helper accepts:

```powershell
node .\tools\prepare-replay.mjs 2 --dataset=C:\path\official-test.json
```

The JSON must match the recorded original dataset fingerprint. If the replay helper already restored the manifest and source fetching then failed, retry the same protocol with `node .\experiment-2\bench.mjs prepare` before any provider run. Do not replace difficult tasks, change the seed, or inject reference files.

## What to reuse in your workflow

Separate **shortlist quality** from **choice quality**. This experiment's biggest limitation was the missing answer on 23 shortlists, so focusing only on AI accuracy would hide the search bottleneck. In a different workflow, measure expected-answer coverage and compare with the first search result before deciding whether an AI selector is useful. Build changes in a separate adapter or experiment, not in this frozen run.
